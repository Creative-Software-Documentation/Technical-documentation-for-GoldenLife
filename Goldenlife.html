Golden life Platform API (FULL PROJECT OVERVIEW)

About this API

This Laravel based REST API powers a multi-role Golden life Platform that connects Students (customers/resellers), Vendors (product sellers) and Instructors (course sellers) under a single system. The platform combines e-commerce (product purchase & delivery), an online course/learning marketplace, a digital wallet with send-money/withdraw features, subscription plans, share purchase, and a support/ticketing system — all controlled from one Admin Panel.

How the API is organized

Every route below is taken directly from routes/api.php. Routes are grouped by the role that consumes them (Student, Vendor, Instructor) and by feature (Product, Course, Location, Bank, Notification, FAQ, Ticket, Chat, Subscription, Share, Hospital). Most protected routes use Laravel Sanctum (auth:sanctum) issued after OTP/Password login; a smaller set of legacy/admin-facing routes use API token guard (auth:api). Routes without any tag below are public.

Base URL & Requirement

Framework

Built on Laravel and consumed by web / mobile apps as a JSON REST API. All endpoints below are relative to your API base URL, e.g. https://example.com/api.

Authentication Guards
  • auth:sanctum — Token issued to Student / Vendor / Instructor after login (send as Authorization: Bearer <token>).
  • auth:api — Token guard used mainly on legacy/admin-consumed transaction & order reporting routes.
  • public — No token required.
Response Format

All endpoints are expected to return JSON. Standard verbs used across the API:

  • GET Read / list data
  • POST Create, login, or action-trigger endpoints
  • PUT Update a specific resource
  • DELETE Remove a resource

Authentication

Three separate identity types can register and log in: Student, Vendor and Instructor. Each has its own registration, OTP verification, login, forgot/reset password, and logout endpoints.

Student Authentication

POST Student Register

This endpoint allows you to register a new student account. An OTP is generated and sent to the provided mobile number via SSLWireless SMS gateway.

HEADERS

Accept: application/json

Example Request
curl --location 'https://example.com/api/student/register' \
--header 'Accept: application/json' \
--form 'name="Rahim Uddin"' \
--form 'email="rahim@example.com"' \
--form 'mobile="01700000000"' \
--form 'password="password123"' \
--form 'password_confirmation="password123"' \
--form 'refer_code="STD2025001"'
Example Response (Body)
{
  "success": true,
  "user_id": 12,
  "message": "Registration successful! OTP sent to 01700000000",
  "api_response": {
    "status": "SUCCESS",
    "status_code": 200,
    "error_message": ""
  }
}
Request Body Parameters
  • name (string, required): Full name of the student.
  • email (string, required): Unique email address.
  • mobile (string, required): 11 digit mobile number matching pattern 01XXXXXXXXX.
  • password (string, required): Minimum 6 characters.
  • password_confirmation (string, required): Must match password.
  • refer_code (string, optional): Affiliate ID of the referrer.

Request Body Parameters
